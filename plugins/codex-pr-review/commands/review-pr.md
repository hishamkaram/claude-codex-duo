Use the two-model-pr-review skill.
Arguments, verbatim: $ARGUMENTS
Read them as: `<pr-number|branch|commit|local> <base-ref> "<stated intent>" [--full] [--workflow] [--via <spec>]` (use `local` or `worktree` as the target for uncommitted changes → head = WORKTREE snapshot; the base ref defaults to HEAD in local mode). Optional flag `--workflow`, recognised anywhere in the arguments (local mode may omit the base ref, so it is not positional): selects the Workflow-tool fan-out for verification (and for the lead review above ~2000 LOC) as described in the skill's `references/workflow-mode.md`. Optional `--via <spec>`, also recognised anywhere: the second-model participants, a comma list of `codex` and `ccr:<alias>` entries (default `codex`; at most one `codex`; 1–8 entries), as described in the skill's Step 0. Optional `--full`, recognised anywhere: use the full output contract instead of the default `compact-v1` tier — both tiers review the same thing and apply every rubric category, but `full` also writes a separate DESIGN section and a category-by-category coverage recital, which measurement showed to be roughly four fifths of a review's length. Any other `--token` is an error to report, not a mode.
